# 프로젝트 연결/분석 안정화

관련 이슈: #289

## 변경 범위

- 프로젝트 연결 확인은 일반 Agent 요청과 분리해 최대 45초 기다린다.
- 이름과 GitHub 계정이 같은 멤버가 중복 등록된 경우 유일한 가입 계정으로 연결한다. 계정이 다르거나 가입 계정이 둘 이상이면 담당 지정이 필요하다.
- Notion 페이지 ID는 완전한 UUID 또는 URL 마지막 경로에서만 추출한다. 제목의 숫자, query의 view ID, fragment의 block ID는 사용하지 않는다.
- 맥락 수집 전체 한도는 기본 120초다. Notion 목록/문서별 조회는 각각 30초로 제한하고, 일부 문서가 실패해도 수집한 자료는 유지한다.
- Notion 문서는 요청 한도를 넘지 않도록 동시에 2개까지만 읽고, 끝난 순서와 관계없이 목록 순서대로 맥락에 넣는다.
- Notion 조회 범위는 기존과 같은 목록 앞 10개다. 임시 3개 제한은 제거했다. 문서의 관련도 기반 선별이나 하위 문서 재귀 탐색을 추가한 것은 아니다.
- 화면은 개수 제한에 따른 생략도 포함하는 경고를 '맥락 수집 안내'로 표시한다. 구체적인 생략/실패 사유는 목록에서 확인한다.
- 결정 섹션의 일반 문단/번호 목록을 보존해 Slack 공지 입력에 전달한다. 소제목/표 행/구분선은 결정으로 보지 않고, 들여쓴 줄은 앞 항목에 이어 붙인다.
- GitHub 증분 색인은 수집 커서보다 5분 앞부터 겹쳐 읽는다. 같은 호출 안에서 재조회하지 않고, 수집 커서는 변경 없음 응답만으로 전진시키지 않아 지연 노출된 이슈를 다음 동기화에서 받는다.

## 확인 항목

1. 숫자 제목/하이픈 UUID/query/fragment가 있는 Notion URL에서 실제 페이지 ID를 추출한다.
2. 네 번째 문서도 조회하고, 10개를 초과하면 생략 건수를 안내한다.
3. 문서 하나가 느리거나 실패해도 정상 문서의 결과는 남는다.
4. 문단형 결정사항을 원문대로 추출하고, 기존 액션 표/담당자/기한 해석은 유지한다.
5. 지연 노출된 이슈가 다음 조회에서 수집되고, 오래된 응답이 최신 색인을 덮어쓰지 않는다.
6. 동일 계정의 중복 멤버와 실제 동명이인을 구분한다.

## 테스트

각 Python 서비스 디렉터리에서 `.venv/bin/python -m pytest -q`, Backend에서 `./gradlew test`, Frontend에서 `npm run build`, `npm run lint`, `node --test tests/*.test.mjs`를 실행한다.

외부 서비스 대신 MCP/HTTP 응답을 주입하는 회귀 테스트다. LLM 판정 정확도/맥락 활용도에 대한 성능 평가는 포함하지 않는다.

## 제한

- 문서 10개 제한과 시간 제한으로 일부 맥락이 제외될 수 있다. 프로젝트별 참고 문서 범위와 관련도 기반 선별은 별도 설계가 필요하다.
- 변경이 없는 동안 커서가 고정되어 겹쳐 읽는 범위가 넓어질 수 있다. 바뀌지 않은 이슈는 임베딩하지 않는다.
- 임의 길이의 GitHub 반영 지연과 모든 동시 발행 경쟁 조건을 보장하지 않는다.
- 모델/프롬프트/중복 판정 규칙/검색 점수/검색 k/공식 평가셋은 변경하지 않았다.
