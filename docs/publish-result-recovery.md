# 티켓 수정·발행 결과 반영

관련 이슈: #290. 기존 #281의 링크 표시 요구사항을 포함한다.

## 제목 수정

검토 대기 티켓에서 제목을 수정할 수 있다. 빈 제목과 255자 초과 입력은 거절한다. 저장한 제목은 내 티켓·미리보기·실제 발행 요청에 동일하게 사용한다.

## 실제 발행과 생략 구분

외부 쓰기를 생략한 결과는 `SKIPPED`로 저장하고 화면에 '발행 생략'으로 표시한다. 실제 발행·연결·갱신 성공으로 집계하지 않는다.

Backend 기동 시 Flyway V3가 기존 티켓 상태 CHECK 제약에 SKIPPED를 추가한다. V1/V2와 기존 데이터는 변경하지 않는다.

## 완료 결과 조회

- Agent는 처리한 배치를 `GET /publish/{batchId}`로 조회할 수 있게 제공한다. 없는 배치는 404다.
- Backend는 RUNNING 배치의 결과를 기본 5초마다 조회한다.
- 배치 ID와 최종 상태를 확인한 뒤 결과를 반영한다. 완료된 배치의 중복 보고는 무시한다.
- 조회 요청은 발행을 재실행하지 않는다.

Agent 결과 캐시는 메모리에 있다. Agent 재시작 이후의 영속 복구나 DB 수준 멱등성은 #263에서 다룬다.

## 결과 링크

분석 결과와 내 티켓은 발행 대상에 맞는 이름과 결과 URL을 표시한다. 기존 githubIssueUrl 필드는 유지하되 Notion·Slack도 각각의 링크로 해석한다.

본문 갱신 후 보조 작업이 실패한 UPDATED 결과도 오류 정보를 응답에 보존한다. 댓글만 다시 보내는 실행 경로는 #291에서 추가한다.

HTTPS, 허용 도메인, 사용자 정보·비표준 포트를 검사한다. Notion의 app.notion.com을 지원하며 다른 서비스의 링크나 유사 도메인은 표시하지 않는다.

## 테스트

- Agent: `.venv/bin/python -m pytest -q`
- Backend: `./gradlew test`
- Frontend: `node --test tests/*.test.mjs`, `npm run build`, `npm run lint`

제목 저장, 생략 상태·집계, 콜백 유실 후 결과 조회, 배치 ID 불일치, 반복 GET의 쓰기 미발생, 도구별 링크와 잘못된 URL을 검증한다. 테스트에서 실제 외부 서비스에 발행하지 않는다.
