# 프론트엔드 디자인 시스템

화면마다 색과 상자 모양이 달라지지 않도록 지키는 최소 규칙이다. 실제 값은 `frontend/src/index.css` 맨 끝의 "디자인 시스템" 블록에 있고, 그 블록이 위의 개별 규칙보다 우선한다.

## 색

| 토큰 | 용도 |
| --- | --- |
| `--accent` `#2459c7` | 주 버튼, 링크, 선택·진행 상태 |
| `--accent-soft` `#eef4ff` | 정보 알림 배경, 선택된 행, 발행 완료 배지 |
| `--accent-line` `#b4c6ea` | 정보 알림 테두리, "할 일" 배지 테두리 |
| `--danger` / `--danger-soft` / `--danger-line` | 실패·오류에만 쓴다 |
| `--text` / `--muted` / `--border` / `--bg` / `--neutral-soft` | 본문, 보조 글, 구분선, 바탕, 대기 배지 |

- 노랑(`--warn`)과 초록(`--ok`)은 새 화면에 쓰지 않는다. 주의가 필요한 상태도 파랑 톤으로 표현하고, 진짜 오류만 빨강을 쓴다.
- 진행 막대처럼 단계를 채우는 표시는 `--accent` 하나로 채우고 남은 칸은 `--border`로 둔다.

## 상태 배지

모든 상태 배지(내 티켓 목록, 티켓 머리말, 결과 확인 목록, 발행 결과, 프로젝트 연결 상태)는 네 가지 톤만 쓴다.

| 톤 | 모양 | 상태 |
| --- | --- | --- |
| 대기·종료 | 회색 바탕 | 미검토/검토 대기, 거절, 발행 생략, 미연결 |
| 할 일·진행 중 | 흰 바탕 + 파란 테두리 | 담당 지정 필요, 승인됨, 발행 중, 권한 확인 필요 |
| 완료 | 옅은 파랑 바탕 | 발행됨, 연결됨, 갱신됨, 연결 확인됨 |
| 실패 | 옅은 빨강 바탕 | 실패, 발행 확인 필요 |

## 알림

- `.notice`는 정보(파랑), `.error`는 오류(빨강)이다. 둘 다 상자는 한 겹만 둔다.
- 다른 상자(발행 실패 상자, 대표 담당 상자 등) 안에 들어간 알림은 테두리와 배경 없이 글로만 보인다. 상자 안에 상자를 겹치지 않는다.
- "저장했습니다" 같은 성공 안내는 화면을 밀어내는 상자 대신 `Toast` 컴포넌트로 오른쪽 아래에 잠깐 띄운다. 오류는 토스트로 띄우지 않고 그 자리에 남긴다.
- 발행 결과처럼 화면이 바뀌어도 남아야 하는 안내는 `NotificationStack`으로 오른쪽 위에 카드로 띄운다. 성공·정보는 8초 뒤 사라지고(마우스를 올리면 멈춤), 일부 실패·실패는 사용자가 닫을 때까지 남는다. 흰 카드에 제목·한 줄 요약·링크만 두고, 일부 실패·실패만 제목을 빨갛게 한다.

## 간격과 모서리

- 간격은 `--space-1`(4px), `--space-2`(8px), `--space-3`(12px), `--space-4`(16px), `--space-6`(24px), `--space-8`(32px)만 쓴다.
- 모서리는 상자 `--radius`(8px), 배지 `--radius-pill`이다.

## 문구

- 사용자가 몰라도 되는 내부 단계나 용어(중복 판단, 색인, 맥락 파악 등)는 화면에 쓰지 않는다.
- 입력 필드는 위에 라벨을 두되, 선택창처럼 placeholder로 뜻이 충분하면 라벨을 생략하고 `aria-label`만 둔다.
